# MARIA — Development Roadmap

This document describes the phased development plan for MARIA. Each phase builds on the previous one. We do not skip phases.

---

## Phase 1 — Foundation *(current)*

**Goal:** Establish project structure, architecture, and core infrastructure.

- [x] Define project vision and goals
- [x] Design modular architecture
- [x] Create repository structure
- [x] Write documentation (README, ARCHITECTURE, SECURITY, ROADMAP)
- [ ] Set up Python virtual environment and dependency management
- [ ] Implement configuration system (Pydantic settings)
- [ ] Implement secure credential storage (encrypted `.env` or keyring)
- [ ] Create base logging infrastructure
- [ ] Create the application entry point (`python -m maria`)
- [ ] Write initial tests

**Deliverable:** A runnable skeleton that loads configuration, manages secrets safely, and logs output.

---

## Phase 2 — AI Provider Layer

**Goal:** Connect to AI providers with a provider-agnostic interface.

- [ ] Define abstract `AIProvider` interface
- [ ] Implement Google Gemini provider
- [ ] Implement OpenAI provider
- [ ] Implement Anthropic Claude provider
- [ ] Implement OpenRouter provider
- [ ] Implement Ollama (local) provider
- [ ] Build provider registry and model router
- [ ] BYOK (Bring Your Own API Key) support
- [ ] Provider health checks and fallback
- [ ] Unit tests for all providers

**Deliverable:** A system that can send prompts to any configured AI provider and receive responses.

---

## Phase 3 — Agent Core & Tool System

**Goal:** Build the agent loop and extensible tool framework.

- [ ] Design agent loop (receive → think → act → respond)
- [ ] Create `Tool` base class and tool registry
- [ ] Implement core tools:
  - [ ] File system operations (read, write, list, search)
  - [ ] Terminal command execution (with sandboxing)
  - [ ] System information queries
- [ ] Permission system — tools declare required permissions
- [ ] Human-in-the-loop confirmation for dangerous actions
- [ ] Tool result formatting and error handling
- [ ] Conversation history management
- [ ] Unit and integration tests

**Deliverable:** An agent that can hold a text conversation and execute approved tool calls.

---

## Phase 4 — API Server & Web Interface

**Goal:** Expose MARIA through a FastAPI server with a web-based chat UI.

- [ ] FastAPI application with REST endpoints
- [ ] WebSocket endpoint for real-time chat
- [ ] Session management
- [ ] Simple web chat UI (HTML/CSS/JS — no heavy framework)
- [ ] Authentication for the web interface
- [ ] Rate limiting and input validation
- [ ] API documentation (auto-generated by FastAPI)

**Deliverable:** A locally-hosted web interface for chatting with MARIA.

---

## Phase 5 — Memory & Context

**Goal:** Give MARIA long-term memory and context awareness.

- [ ] SQLite-backed conversation storage
- [ ] Conversation summarization for context window management
- [ ] Vector memory for semantic search (embeddings)
- [ ] User preference learning
- [ ] Session continuity across restarts

**Deliverable:** MARIA remembers past conversations and learns user preferences.

---

## Phase 6 — Voice Interaction

**Goal:** Enable natural voice conversation.

- [ ] Speech-to-text (Whisper or Gemini Live API)
- [ ] Text-to-speech (natural-sounding voice)
- [ ] Bangla and Hindi language support
- [ ] Wake word detection (optional)
- [ ] Streaming voice for real-time conversation
- [ ] Push-to-talk and continuous listening modes

**Deliverable:** Users can speak to MARIA and hear responses in Bangla, Hindi, or English.

---

## Phase 7 — Advanced Tools

**Goal:** Expand MARIA's capabilities with powerful tools.

- [ ] Browser automation (Playwright or similar)
- [ ] Git/GitHub integration
- [ ] VS Code / IDE assistance
- [ ] Web research and summarization
- [ ] Coding agent capabilities (code generation, review, debugging)
- [ ] Windows automation (Win32 API, UI Automation)
- [ ] Screenshot analysis

**Deliverable:** MARIA can control the browser, write code, manage git repos, and automate Windows tasks.

---

## Phase 8 — Android Client

**Goal:** Build a mobile companion app.

- [ ] Android app (Kotlin + Jetpack Compose)
- [ ] Secure communication with PC (encrypted WebSocket or similar)
- [ ] Voice input on mobile
- [ ] Notification system
- [ ] Remote PC control from phone
- [ ] Offline capabilities

**Deliverable:** An Android app that connects to the MARIA server on your PC.

---

## Phase 9 — Autonomous Mode & Integrations

**Goal:** Allow MARIA to work semi-autonomously with strict guardrails.

- [ ] Sleep mode / background monitoring
- [ ] Autonomous task execution with permission boundaries
- [ ] WhatsApp Business API integration (where officially supported)
- [ ] Messenger integration (where officially supported)
- [ ] Email integration
- [ ] Calendar integration
- [ ] Scheduled tasks and reminders

**Deliverable:** MARIA can perform approved background tasks and communicate through messaging platforms.

---

## Phase 10 — Polish & Distribution

**Goal:** Prepare for public release.

- [ ] Windows installer (MSI or MSIX)
- [ ] Android APK / Play Store listing
- [ ] Comprehensive documentation
- [ ] Contribution guidelines
- [ ] CI/CD pipeline
- [ ] Security audit
- [ ] Performance optimization
- [ ] User onboarding experience

**Deliverable:** Downloadable, installable MARIA for Windows and Android.

---

## Guiding Principles

1. **Ship incrementally.** Each phase produces something usable.
2. **Security first.** Never compromise on permission checks or credential safety.
3. **Stay modular.** Every component should be replaceable.
4. **Test everything.** No phase is complete without tests.
5. **Document as you go.** Code without documentation is incomplete.

---
